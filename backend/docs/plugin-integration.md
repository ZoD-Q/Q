# Q 插件接入规范

本文件规定 Q（小Q）后续建设开放插件宿主时的技术与验收要求，供 Q 开发者、第三方插件开发者和 AI Agent 使用。基线日期：2026-10-18。

**当前状态（2026-10-19）：** 已实现有界 MCP 2026-07-28 HTTPS 客户端、Card/Catalog/网页/域名发现、个人连接、OAuth/CIMD、工具/资源/提示词、显式确认及聊天提案续答。原生图片查看器使用标准资源接口；MCP Apps HTML 沙箱、输入请求交互、后台任务及公共索引未实现。本文仍包括完整目标合同，实际支持范围见 [MCP 宿主](../../mobile/docs/mcp-host.md) 与 [逐请求协议依据](reference/mcp-2026-wire-source.md)。开发前同时阅读 [根协作规范](../../AGENTS.md)。

2026-10-21 源码补充：Q 自带的银行模拟插件使用服务端受信 `bank_demo` 执行器和内部 URN，通过既有提案/确认链调用 `ledger::bank_demo`。它们不是第三方 MCP 服务，不声明远程 Card、OAuth 或银行官方接入；以下 HTTPS/MCP 基线继续适用于远程插件。第三方 Card 元数据及添加请求不能选择内置执行器。详见 [银行插件合同](../contracts/banking.md)。

## 1. 来源、角色与实施范围

本规范将用户提供的 [K Protocol 开发规范原文](reference/k-protocol-baseline.md) 映射到 Q 宿主。原文文件按字节保留，参考文件不是新的开发任务，也不自动授权部署插件、修改其他宿主、调用第三方业务或执行付费操作。当前用户任务及已有授权决定实施范围。

| 角色 | 负责 | 不应混入的职责 |
| --- | --- | --- |
| Q 宿主 | 发现与添加、MCP Client、用户连接、授权协调、调用编排、Apps 沙箱、个人目录与公共索引 | 替插件绕过业务权限、执行未经允许的外部操作 |
| 插件发布者 | 自行控制稳定地址与 MCP 服务、业务逻辑、服务端权限、可选交互资源及用户关系 | 默认修改 Q 主应用，代替宿主实现全平台搜索或抓取 |
| 上游系统 | 在许可范围内提供数据、账户或业务 API | 因插件“已添加”就默认开放全部数据 |

Q 的服务端业务遵循 Rust + PostgreSQL 架构；独立第三方插件可使用任何兼容标准的技术栈。已有 REST API 可以通过 MCP 适配层复用，也可直接实现 MCP 业务能力，不强制先造 REST API。

**开发者账号、Registry 注册、人工上架审核不是发布、添加或调用的前置条件。** 可选开发者控制台、统计或 API Key 产品不能重新引入这些门槛。服务要求用户登录、订阅或具体操作权限不违反这一原则。

## 2. 选定版本与标准边界

| 层 | Q 选用的基线 | 职责 |
| --- | --- | --- |
| MCP | `2026-07-28` | 运行时版本、能力与标准调用 |
| 远程传输 | HTTPS Streamable HTTP | 远程请求与响应 |
| MCP Apps | `2026-01-26` | 对话内 UI 资源、消息与独立生命周期 |
| MCP Server Card | v1 | 连接前身份与端点描述 |
| AI Catalog | `1.0` | 服务发现与链接集合 |

对外插件协议层不得自造 Q/K RPC、事件接口、额外消息封装、固定业务工具名或 UI 描述语言。内部领域事件或队列不因此受限，按实际架构需求设计。业务对象、状态与幂等键由实际工具合同定义，不强行加全平台统一业务字段。

以下是采用标准时必须区分的层级：

- MCP `2026-07-28` 使用无状态、逐请求的版本/能力元数据；实现相应 `_meta` 与 HTTP 版本头规则，不能把旧版 `initialize` 握手样例仅替换日期后使用。MCP Apps 的 `ui/initialize` 仍是独立 UI 生命周期。
- 上游要求服务端支持 `server/discover`，允许客户端按场景发现；**Q/K 约定进一步要求宿主先调用它**，再按返回能力与权限调用业务。
- 上游授权规范对 CIMD 使用推荐级别；**Q/K 对需要账户身份的服务进一步要求授权客户端和服务器双方支持 CIMD**。这不是所有 MCP 实现天然具备的能力。
- Server Card 属于扩展规范，SEP 已为 Final；其发现说明仍有 draft 标记。AI Catalog 是独立发现格式，所选 `1.0` 材料仍标记为 draft，不能把版本号解读为已完成最终标准；它不是 MCP 核心协议。上游 Catalog 的更多表达方式不自动扩展 Q 已选定的 URL 接入合同。
- 实现前核对选定版本文档和 SDK 的实际支持程度，锁定依赖及 schema 版本并记录兼容性缺口。不能因 SDK 尚未支持就自行替换协议，也不能声称已完成 schema 验证而没有实际运行证据。

## 3. 发布与连接前发现

### 3.1 每个插件的 Server Card

每个插件必须有独立、稳定、可解析的 HTTPS Card URL，响应媒体类型为 `application/mcp-server-card+json`。至少声明一个 HTTPS Streamable HTTP 端点，支持 MCP `2026-07-28`。具体字段遵循锁定的 v1 schema，原文提供了结构示例；部署验收必须检查真实响应和所用 schema。

Card 仅描述服务身份与连接，不重复声明工具、资源、实时能力或授权配置。授权服务器通过标准授权发现机制获得，工具通过运行时获取。

所有者是可选的发布者自声明展示信息。Q 使用 Card v1 允许的 `_meta` 扩展：`_meta["com.kaicloudpay.q/owner"] = {"name":"mandow"}`。这不是新增 MCP RPC 或上游标准认证字段，也不绑定 Q 账号、权限或服务身份。名称去除两端空白后为 1–80 个 Unicode 字符，不含控制字符和双向方向/覆盖/隔离字符；缺失或格式无效时不展示所有者，但不因此拒绝合法 Card。其他 `_meta` 原样保留。调用确认记录保留当时的所有者声明，服务后来修改名称不会改写历史。

服务标识使用规范化的 **Card URL**，保留原始 URL 供追溯。规范化不能改变有效路径或查询语义：保留路径大小写、有效参数、重复参数及其顺序，不因“清理链接”删参数、重排查询或随意去掉尾斜杠。不得只按 `name`、Catalog `identifier` 或展示标题合并服务或权限。

分别存储发现来源、Card 来源和实际 MCP 端点。跨域 Card 或端点引用可以存在，但不授予跨来源的权限、Cookie 或令牌共享；重定向也不是转交凭据的许可。

### 3.2 四类输入

Q 的接入界面默认自动识别入口。纯域名按域名规则查根 Catalog；完整 URL 按该地址实际返回的媒体类型及静态发现声明识别，复用已获取的响应，并保留路径与有效查询参数。高级选项仍允许显式指定四类入口；自动识别不扩大网络访问或授权范围。

| 输入 | 处理规则 |
| --- | --- |
| 域名 | 读取 `https://域名/.well-known/ai-catalog.json`，筛选 MCP Server Card 条目 |
| 介绍页 HTTPS URL | 读取该页的静态 `rel="ai-catalog"` 或 HTTP `Link` 声明，解析相对链接；不执行页面脚本 |
| Catalog HTTPS URL | 验证媒体类型、`specVersion` 与条目，保留其服务范围 |
| Card HTTPS URL | 验证并展示对应服务及实际来源，进入添加流程 |

无法识别具体页面时明确失败，不能丢弃路径、转查全站 Catalog 或猜测其他端点。一个服务展示待确认卡片，多个服务让用户选择，禁止自动添加整个目录。面向单插件的介绍页应只引用相应服务集合。

提供**域名发现**时，发布者必须在 `/.well-known/ai-catalog.json` 发布根 Catalog，媒体类型为 `application/ai-catalog+json`。每个插件都要稳定 Card，根 Catalog 则是域名发现的条件性要求，二者不能混淆。Q 采用 `specVersion`、`entries` 及条目 `identifier` / `type` / `url` 结构：

```json
{
  "specVersion": "1.0",
  "entries": [
    {
      "identifier": "urn:air:acme.example:mcp:calendar",
      "type": "application/mcp-server-card+json",
      "url": "https://acme.example/mcp/calendar/server-card"
    }
  ]
}
```

以上域名为占位示例。Catalog 可以指向其他域名的 Card；上游允许的内联形式不能代替本约定中每个插件的独立稳定 Card URL。

介绍页可声明：

```html
<link rel="ai-catalog" type="application/ai-catalog+json"
      href="/plugins/calendar/catalog.json">
```

二维码原样编码普通 HTTPS 介绍链接或其他受支持 HTTPS 入口，不另造专用 scheme、格式或中心短链。链接不得含令牌、凭据或私有业务数据；扫码仍需展示来源并确认添加，不自动授权或执行业务。

## 4. 运行时与工具合同

获取并校验端点后，Q 必须调用 `server/discover`，以实时版本、能力和当前用户权限为准。发现本身需要身份时先完成所需授权，再取得可用能力；不能为了“先发现”绕过鉴权。

| 能力 | 列表 | 使用 |
| --- | --- | --- |
| 工具 | `tools/list` | `tools/call` |
| 资源 | `resources/list` | `resources/read` |
| 提示词 | `prompts/list` | `prompts/get` |

只调用服务实际支持的标准方法。Card 不能代替运行时检查，公共抓取缓存也不能作为当前用户的权限依据。

- 输入用 `inputSchema`；有结构化输出时用 `outputSchema` 与 `structuredContent`。输出应通过对应校验，业务错误不能伪装成成功内容。
- **工具始终提供可理解的文本结果**，供模型、无障碍和 UI 降级使用；只返回界面或截图不满足要求。
- 合同写明真实业务工具名、输入输出、身份与对象范围、读写性质、费用、状态、错误、超时与限制。工具注解和描述是第三方声明，不替代鉴权或可信业务判断。
- 写操作按业务提供幂等和结果查询/恢复机制。结果未知时不盲目重发，不因 UI 重开、网络重连或授权刷新而重复执行。
- 元数据、错误、缓存与通知遵守选定 MCP 规范，不额外套一层 Q 消息。

## 5. 添加、授权、执行

| 动作 | 仅表示 |
| --- | --- |
| 添加 | 用户确认服务并保存连接关系，可处于待授权状态 |
| 授权 | 用户授予明确的账户访问、资源与业务权限 |
| 执行 | 在当前用户意图、有效权限与宿主策略范围内调用工具 |

三者不能合并。添加、扫码、目录收录不自动授权账户访问、写入或收费业务；已获得且仍有效的授权可在原范围内使用，不要求无意义地重复确认。

需要账户身份的服务必须采用 MCP 授权机制，通过 Protected Resource Metadata 发现授权服务器，且授权客户端和服务器双方支持 CIMD。记录实际授权资源、主体、范围与有效期；按标准执行令牌获取、刷新、撤销及回调校验。CIMD 不是 Registry 注册或逐家人工登记客户端。

服务端始终校验用户、租户、对象归属和操作权限；宿主传来的用户 ID、界面显示、工具名称或 `visibility` 都不是可信授权。凭据按用户连接、来源与授权资源隔离，不能下发给插件 UI、写进公共目录或跨插件复用。

## 6. MCP Apps 界面

Q 负责实现符合所选版本的 Apps 宿主，声明客户端能力 `io.modelcontextprotocol/ui`。提供界面的插件在工具元数据中声明标准 UI 资源：

```json
{
  "_meta": {
    "ui": {
      "resourceUri": "ui://calendar/planner.html",
      "visibility": ["model", "app"]
    }
  }
}
```

宿主经 `resources/read` 获取 `ui://` 资源，内容类型为 `text/html;profile=mcp-app`。界面运行于宿主管理的隔离沙箱，执行 MCP Apps 的 CSP、通信与权限规则。Web 宿主必须通过与宿主不同 origin 的中间 sandbox proxy 承载 View 并转发标准消息，不能以单层同源 iframe 代替。移动端可评估隔离的 WebView 容器；只有完整验证标准和平台隔离之后才能认定支持 Apps，不能把任意网页直接当插件界面。见 [Apps 沙箱规范](https://github.com/modelcontextprotocol/ext-apps/blob/main/specification/2026-01-26/apps.mdx#sandbox-proxy)。

- UI 使用独立 `ui/initialize` 生命周期；不能用它初始化远程 MCP 连接。等 UI 完成标准就绪流程后再传入工具数据。
- 模型可生成布局描述、表单或业务数据，由预声明 UI 资源渲染；不引入自定义 Q 组件协议，不把普通工具文本直接执行为 HTML。
- 交互继续调用相应业务工具，不走通用 Q/K 事件接口；仅界面工具用 `visibility: ["app"]`，但仍须服务端鉴权。
- UI 无法取得宿主凭据、其他插件或用户的数据；仅经受控宿主通道访问获准能力，CSP 不允许的资源须明确失败。
- UI 加载失败使用文本降级，**不得再次执行业务工具**。恢复通过业务查询或资源读取；关闭界面不代表撤销、退款或取消业务。

原始材料中的 Lark 通信图没有随文本提供，不能虚构其消息名与顺序；以选定版本的 MCP Apps 文档核对实现。

## 7. 个人添加与公共索引

逻辑上分开保存三类记录；此处不预设数据库表名：

| 记录 | 内容 |
| --- | --- |
| 服务记录 | 按 Card URL 标识的服务、连接元数据、版本与校验状态 |
| 目录条目 | 发现来源、展示与搜索元数据、公开条件和同步状态 |
| 用户连接 | 用户/工作区归属、授权状态、私有配置与凭据引用 |

用户确认添加且结构、来源校验通过后，立即创建或合并相应服务记录并保存连接；需要授权时明确标记待授权。公共目录同步独立运行，索引暂不可用不能阻止已知服务的个人添加与连接。

公共收录必须同时满足：发布者将通用 Card 主动列入其自己的公开 AI Catalog；宿主验证发布者来源；独立抓取器匿名访问；抓取与索引许可允许。第三方目录转贴只是发现线索，不代替发布者公开声明。

抓取器遵守 `robots.txt` 和 Card 响应头 `X-Robots-Tag: noindex`。无法确认允许抓取时不创建新公共条目；不满足公开条件的连接仍可保存在相应个人或工作区插件库并按权限使用。`noindex` 不是访问控制，私有服务仍须鉴权。

公共库只存公开服务描述，禁止纳入私有 Catalog、用户/租户配置、凭据、授权后能力列表、聊天、工具结果和 UI 数据。公开 Card 也不意味着服务免授权。

发布者撤回声明或设置禁止索引时，在同步中撤下公共条目；用户删除连接只清理其对应连接与凭据，不删除其他用户连接。外部 Registry 可以作为线索或互通目录 API，但绝不是接入前置门槛。

## 8. 安全、变更与失败处理

| 场景 | 必须执行 |
| --- | --- |
| 来源信任 | 展示实际来源；名称、图标、目录收录与工具描述不构成安全背书；插件内容不得成为宿主高优先级指令 |
| 公共网络请求 | HTTPS，限制大小、超时与重定向；每次 DNS 解析、实际连接与重定向检查目标，防止 SSRF/DNS 重绑定访问回环、内网或云元数据 |
| 内部插件 | 使用工作区受控网络与单独授权路径，不为公共抓取器开内网例外 |
| 跨插件编排 | 由宿主协调，每个服务独立授权，不能因组合使用获得其他插件权限 |
| 外部影响 | 统一检查用户意图与有效权限，按业务处理费用、写入和取消；UI 状态变化不扩大权限 |
| 未知结果与重试 | 查询或按原业务幂等请求恢复，不创建新操作冒充重试 |
| 普通更新 | HTTP 缓存与条件请求；描述更新可自动同步 |
| 敏感更新 | MCP 端点、授权主体或权限范围变化重新校验；不得自动搬移旧凭据或扩权 |
| 移除连接 | 停止该连接后续调用并清理对应凭据；在途或已完成业务另按实际状态处理，不假称自动回滚 |
| 错误状态 | 分别显示发现失败、授权失败、不可达、工具失败、UI 失败与结果待确认，不显示成添加/执行成功 |

来源数据/API 的合法可用性和上游权限按具体任务核对。样例、模拟数据与部署网页不能代替真实业务联调。

## 9. 开发交付与验收

开工前确定是插件侧、Q 宿主侧还是双方联调；确认实际能力、外部影响、授权范围与兼容性缺口。先从代码和来源查清事实，只就真正缺失的决定提问。

插件侧必须交付稳定 Card、运行中的兼容 MCP 服务、业务合同与验证记录；提供域名发现时交付根 Catalog，需要身份时交付标准授权/CIMD 支持，提供 UI 时交付 Apps 资源与文本降级。介绍页和二维码为推荐便利入口，不是额外中心化发布门槛。

| 验收主题 | 可观察的通过证据 |
| --- | --- |
| 四类入口与多服务 | 域名、介绍页、Catalog、Card 均正确解析；路径保留；多条目选择；无效输入明确失败 |
| Card 身份 | 稳定 URL、媒体类型、schema 与端点检查；同名不同服务不合并权限；跨域不泄露凭据 |
| 运行时 | 真实 `server/discover` 响应，按能力和当前身份列出、调用工具/资源/提示词 |
| 授权 | 添加、待授权、已授权与执行状态独立；Protected Resource Metadata/CIMD 流程及拒绝、过期、撤销正确 |
| 工具合同 | 实际输入输出匹配 schema，文本可理解，结构化结果与业务错误如实返回 |
| Apps | 宿主能力声明、资源读取、独立初始化和就绪顺序正确，沙箱/CSP 阻止越权 |
| UI 降级 | UI 失败不重复写入；app-only 工具仍鉴权；恢复用查询，关闭不虚构取消 |
| 添加与索引 | 个人记录及时保存；公共索引检查发布者声明、匿名抓取、robots/noindex；公共同步失败不阻塞连接 |
| 数据隔离 | 不同用户/工作区/插件互相隔离；私有目录、能力、结果和 UI 数据不进入公共库 |
| 更新与断开 | 条件请求生效，敏感变更重新校验，断开停止调用并清理对应凭据 |
| 副作用与失败 | 重复、并发、超时、未知结果按业务幂等恢复；费用/写入有权限检查；错误状态区分 |

每次交付分别列明 **网页是否部署、MCP 是否可连接、授权是否完成、Q 是否联调通过、真实业务是否验证**。附环境、版本、日期、脱敏证据与未覆盖情况；只把实际通过的项写为完成。
