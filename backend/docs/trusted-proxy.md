# 公网登录的可信客户端地址

本文描述可信代理实现及部署接线要求，不代表服务器已经切换或公网多人验收已经完成。

## 原因与保持的限制

`/v1/auth/register` 与 `/v1/auth/login` 共用每来源 30 次 / 60 秒的限制。旧实现仅使用 Rust 看到的 TCP 来源；公网请求经过容器网关后，不同用户会共用该来源的配额。外层宿主 Nginx 已经校验负载均衡来源并重建 `X-Forwarded-For`，但容器网关原先会再次覆盖这个地址。

新实现只修正来源身份，不提高现有限额：每个客户端地址仍为 30 次 / 60 秒，每账号注册与登录共用 10 次 / 60 秒，密码计算全局最多 4 个并发。同一 NAT 下的用户仍共用一个公网地址配额。这个改动不提供每日 AI 预算，也不代表 100 人性能测试已经通过。

## 每一跳的信任边界

1. 公网负载均衡进入宿主 Nginx。继续使用 [专属入口](../deploy/nginx-q-domain.conf) 中已核对的原始 TCP 来源门禁、`real_ip` 处理和重建的单地址 `X-Forwarded-For`；不直接保留客户端原始转发链。
2. 宿主 Nginx 访问服务器回环 `127.0.0.1:18787`，由 Docker 映射至容器网关。网关使用 `map $remote_addr`，只在请求对端与明确配置的宿主桥接地址完全匹配时保留非空 `X-Forwarded-For`；其余来源全部重写为 TCP 地址。`Forwarded` 清空。
3. Rust 只在 TCP 对端属于 `Q_TRUSTED_PROXY_IPS` 的精确 IP 集合时解析 `X-Forwarded-For`。必须恰好一个头、恰好一个有效 IP 字面量；缺失、重复、非法、多地址、带端口、主机名、CIDR 均回退为 TCP 对端。IPv4 与 IPv4-mapped IPv6 归一化为同一个 IPv4 地址。其他 IPv6 地址保持独立。

不要直接信任任意 XFF、选择转发链最左地址、信任全部 RFC 1918 网段，或仅修改 Rust 而遗漏内层网关。

## 运行配置

`TrustedClientIpPolicy::parse` 不读取环境变量。可执行入口启动时读取 `Q_TRUSTED_PROXY_IPS`，调用解析函数并设置 `AppState`；`AppState::new` 和测试默认使用空策略。未设置或空白值表示不信任任何代理。配置只支持逗号分隔的精确 IP，最多 64 项、4096 字节；非法项应让启动失败，不静默忽略。

容器网关读取 `/etc/nginx/trusted-host-proxies/*.conf`。没有匹配文件时不信任任何宿主代理；不得把回退至共享配额误报为已经完成接线。部署工具应在受限配置目录生成文件，并将该目录以只读方式挂载到上述位置。每行格式为 `精确IP 1;`，其中地址必须先经过 IP 字面量校验，不能直接拼入任意环境文本。这里的 `map` 使用精确键，不使用正则或 CIDR。

实际地址必须从目标服务器的 Docker 网络元数据与连接观察取得：

- 网关允许列表填写网关实际看到的宿主桥接 TCP 地址。
- Rust 允许列表填写 API 实际看到的网关容器 TCP 地址。
- 两者不是同一个配置值，也不能假定它们等于 `127.0.0.1`。

应为业务使用的专属 Docker 网络及网关建立经冲突核对的固定地址分配，或在每次重建后重新生成并核验配置。不能复制示例 IP 作为生产地址，也不能为适应动态地址而扩大到整个私网。发布失败或地址变化后，默认回退仍保护来源限流，但可能恢复为多用户共享桶；必须通过发布后验收发现该情况。

网关仅决定哪些来源可以传递候选地址；最终单地址语义由 Rust 校验。重复 XFF 如果被代理合并为逗号列表，Rust 同样拒绝。正常请求经宿主入口重建后应始终只有一个 IP。

## 验收

本地单元测试使用实际 `AuthLimiter` 检查：

- 同一可信代理后的 A、B 客户端各自获得 30 次配额；A 第 31 次被拒时 B 仍有完整配额；窗口到期恢复。
- 非可信 TCP 来源不断伪造不同 XFF，不能更换限流桶。
- 默认空策略、错误配置、缺失或重复头、多地址列表、无效值均不扩大信任。
- IPv4-mapped IPv6 不产生第二个信任身份或配额。

集成负责人还须在隔离测试环境验证两层 Nginx 与 Rust 的实际链路：可信宿主路径传递真实客户端；未列入允许列表的来源不能利用伪造头；网关重建后信任地址仍一致；账户级配额保持不变。使用隔离 PostgreSQL 库，不对业务数据库运行注册压测。

Rust 运行 `cargo fmt --check`、`cargo clippy --all-targets --all-features -- -D warnings`、单元测试及身份 PostgreSQL 集成测试；部署配置运行实际 Nginx 语法和链路检查。公网验证需要独立记录实际客户端地址分离与防伪造结果，配置文本检查不能替代真实链路证据。
