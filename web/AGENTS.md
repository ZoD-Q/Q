# 小Q Web 管理工作台规范

先读[根规范](../AGENTS.md)。2026-11-06用户明确要求正式后台只显示真实数据、仅黑/青/红，此要求优先于旧演示和三主题规范；移动端视觉不在本任务范围。

- `/q-admin/`及钱包子路由统一使用Q登录与服务端maker/checker授权。隐藏页面不能代替鉴权，普通Q账号不得读取操作员数据。
- 业务数据只能来自真实合同接口；不提供假指标、假订单、示例账号、伪操作员、场景切换或假成功。缺接口的模块移出导航和搜索，旧地址只显示未接入。测试夹具只在测试文件或测试目录，不能被生产入口导入。
- 只允许黑`#000`、青`#0ff`、红`#f00`及其透明层。黑为背景，青为正文/边框/焦点/可用操作，红为错误/危险。状态同时使用文字或图标；保持键盘、对比度、双语与375px布局。无三主题切换、远程字体或彩色演示图片。
- 使用现有React/Vite，接口复用`mobile/shared/src/generated.ts`，不得手改生成类型或引入第二套身份/账本。未授权时不改后端合同。
- 令牌仅内存；未知写入保留API来源+账号的最小恢复引用，原文件、备注和凭据不持久化。保留退出、切号、401、迟到响应与BFCache隔离。
- 正式凭据入口仅精确官方HTTPS origin；本地联调须双重显式开关和回环来源。生产构建必须清除本地测试地址。
- 所有正式HTML同源CSP、no-store，静态资源缺失404；不能通过放开任意跨域解决集成问题。
- 改动运行Web typecheck、lint、test、build、test:e2e；发布工具同时运行Shell语法、Python与真实本地Nginx路由测试。真实Rust+隔离PG验收单独记录，不把受控接口测试称为生产实账。更新README、接口映射和验收记录。
- 保留其他工作区、共享分支、数据及未提交改动；暂存、提交、推送和发布由集成负责人按用户授权安排。本轮不操作服务器或角色权限。
