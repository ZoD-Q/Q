# 小Q frontend development contract

- Repository top-level directories are `web/`, `mobile/` and `backend/`. This file governs the mobile workspace: `native/` is the Expo iOS/Android app; `shared/` contains wire types and pure shared utilities. The independent future browser product belongs in sibling `../web/`.
- Current frontend design work is independent of the backend. From this directory, `npm run dev` starts only the Expo UI preview; `npm run dev:native` starts native Expo development. Never make the default UI launcher start PostgreSQL or the Rust API.
- Read `../backend/contracts/api.md` before changing API-dependent behavior. `../backend/contracts/openapi.json` is the machine-readable wire contract; `npm run api:generate` regenerates `shared/src/generated.ts`. Never hand-edit generated types. The integration owner coordinates contracts, shared types, dependency locks and SQL migration ordering.
- All backend business logic stays under `../backend/` and uses Rust with PostgreSQL. identity owns credentials and sessions; profiles owns editable personal fields; ledger exclusively owns accounts, immutable entries and transfers; payments is a future/mock provider boundary and must not write balances directly.
- Only simulated QDC units exist in the preserved wallet implementation. Mark money-related UI as demo. Never connect real payment or financial services as an incidental change. Frontend prototypes must not alter or reset existing account or ledger data.
- Amounts use integer minor units. Server-side transfer debit and credit commit in the same database transaction; authorization, nonnegative user balances, request idempotency and deterministic locking remain backend invariants.
- Secrets stay server-side. Existing native sessions use SecureStore. Password hashing and opaque session-token hashing belong to the backend; public demo credentials must not imply production readiness.
- Keep Expo routes under `native/src/app`, screen bodies outside it. Existing semantic themes are light, dark and warm; centralize Chinese and English copy. Follow the current user's design instructions when they change the active frontend presentation.
- Agent ownership must not overlap. Ask the integration owner before touching another agent's directory or shared files. Avoid empty speculative implementations for future modules.
- Verify changes at the appropriate layer: frontend type/lint/export and actual UI inspection for UI work; real PostgreSQL API checks when backend behavior changes. Historical backend tests and data must be preserved during frontend-only work. Record runtime limits honestly.
