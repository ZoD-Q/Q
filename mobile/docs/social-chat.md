# 小Q 社交聊天

事实核对：2026-10-19。本文件说明本次仓库实现与验收边界，不代表服务器已部署或生产就绪。接口字段、错误与权限以 [Social API 合同](../../backend/contracts/social.md) 和 [OpenAPI](../../backend/contracts/openapi.json) 为准；提交检查仍遵循 [根协作规范](../../AGENTS.md)。

## 入口与同一个 Q 账号

AI 对话仍是首页。顶栏右侧的消息气泡进入独立的消息中心，显示未读数；中心保留“消息 / 好友 / 通知”，添加好友在中心右上角。好友资料可以进入对应私聊。侧栏设置展示真实昵称与 `@handle`，“我的 Q 号与邀请”进入添加与分享页面。

页面使用 Expo Router 的 `/social`、`/social/add`、`/social/friend`、`/social/conversation` 路由，主体在 `mobile/native/src/prototype/social/`，不把社交混入 AI 会话列表或插件服务目录。进入社交页会使底层首页失去焦点：AI 停止当前生成但保留同一账号的本次会话状态；视频播放器按路由焦点暂停。

- 复用现有 `identity` 会话和 `profiles` 资料。内部主键是用户 UUID，公开 Q 号是现有唯一 `handle`，没有另造数字 Q ID。
- 真实资料包含昵称、简介和四种内置头像；头像上传尚未实现。资料写入使用已有 `/v1/me`，不让客户端修改身份、权限或余额。
- `QAccountProvider` 为设置、社交和 API 工作台提供已验证账号；AI 沿用自己的对话控制器，共享同一会话存储。退出与换号会通知消费者并隔离旧请求，逻辑退出先于物理凭据清理；失败的远端退出可以按原令牌独立重试，不退出后来登录的账号。
- API 的 `locale: zh-CN/en` 显式映射为原型 `zh/en`；`light/dark/warm` 按账号资料映射。API 默认 `warm` 与未登录原型默认 `light` 不混为一项默认值。
- 原生会话令牌在 SecureStore；Web 预览令牌仅在内存，不写入 localStorage、邀请链接、二维码或业务日志。

邀请链接为 `xiaoq://social/add?handle=…`，只含公开 Q 号，在已安装小Q的设备中打开。二维码由固定版本 `qrcode-generator@2.0.4` 生成，MIT 许可、纯 JavaScript、无运行时依赖；绘制复用现有 `react-native-svg`。本次没有新增原生组件，也没有实现相机扫码器、未安装应用的网页落地页或应用商店分发。

## 好友与普通私聊

添加好友使用已鉴权的精确 Q 号查询、邀请链接或二维码带入的 Q 号。先确认资料、发送申请，再由对方接受或拒绝；双向申请也不会自动成为好友。没有公开用户目录、模糊搜人、上传通讯录或陌生人直接发送消息。

好友资料支持个人备注、免打扰、删除、拉黑与举报。备注、免打扰为个人设置；免打扰会影响应用内未读汇总，不代表已接通系统推送。解除拉黑不恢复好友关系。删除或拉黑后停止发送与亲密度累计，清理该关系剩余阅后正文；普通历史仍可读。重新添加会建立新会话，亲密度从零开始。

首版只有一对一文字，正文最多 2,000 个 Unicode 字符，没有群聊、图片文件、语音通话或视频通话。普通消息持久化在 PostgreSQL，消息中心预览最多返回 160 个 Unicode 字符；完整正文通过会话消息接口读取。

每条发送意图先生成 `client_message_id`。结果未知时保留原编号，查询原消息或重试相同载荷，不新建一条消息来试探是否发送成功。服务端按发件人去重；同编号改会话、正文或时长返回冲突。已过期的阅后消息不能靠重放重新保存正文。

会话内 `seq` 在双方身份行按 UUID 顺序加锁后分配，与消息一同提交。`after_seq` 只表示已提交的新消息顺序，分页每次最多 100 条；它不是全局时间戳或全局自增游标。好友、拉黑和发送权限在同一事务边界核对。

当前容量是显式限制：每用户最多 200 位好友、双方方向合计 100 条待处理申请、500 个历史会话、200 个拉黑对象。超限返回 `SOCIAL_CAPACITY`，不会悄悄截掉快照列表。读请求、消息发送和其他写操作分别有进程内限频；这些限制不是分布式反滥用系统。

## 阅后消息：开封与已读分开

发送时选择普通文字或单条阅后消息，时长为 30 秒、5 分钟（300 秒）、24 小时（86,400 秒）。`ttl_seconds` 必须明确给出；普通文字传 `null`，不能因漏字段而误存为永久普通消息。

1. 发送后保存消息封套，正文只进入 `social_ephemeral_payloads`。发送响应、消息列表、会话摘要与通知均不返回阅后正文，发送者也不能调用开封接口再次读取自己的正文。
2. 未开封正文最多保留 7 天。接收者联网点击开封，由服务端原子设置首次 `opened_at` 和唯一 `expires_at`。已读回执只推进已读游标，刷新、进入会话和标记已读均不会自动开封。
3. 开封后按选择的时长单独计时，不被原先“未开封 7 天”的截止时间截断。丢失开封响应、多次点击或换设备请求，使用同一绝对截止时间，不重新开始计时。
4. 客户端依据响应中的服务器时间和截止时间，结合请求开始时的单调时钟与墙上时钟计算剩余时间。网络耗时和时钟异常只会保守缩短显示，不延长服务端期限。
5. 服务端读取立即过滤过期或缺失正文，返回 `SOCIAL_MESSAGE_EXPIRED`；后台任务在启动时及每 30 秒清理一次，每轮最多处理 1,000 个仍有正文的过期消息。清理积压不延长可读时间。

开封、过期属于既有封套状态变化，不生成新的 `seq`。前台会话对已加载的阅后封套调用 `ephemeral-state`，每次最多 100 个，优先同步当前已打开正文并轮转其他封套；这样另一设备开封、销毁旧消息也能更新状态。接口校验当前成员和整批消息所属会话，正文恒为 `null`。

离开会话、应用转后台、退出、换号或失去好友关系时，清理当前页面正文、草稿和临时开封状态，并取消旧请求；返回后重新查询服务器。期限届满显示不可用封套，不从旧响应、重试或备份复活正文。

这不是端到端加密实现。应用没有“绝对防截图、防录屏、防翻拍”承诺，也不声称数据库文件、WAL、设备系统或第三方副本已被物理擦除。

## 亲密度与关系标签

亲密度仅使用双向普通消息的发送事实，不分析正文。双方开启时，同一 **UTC 自然日**各自发送过普通消息，最多增加 1 个双向互动日；北京时间的日界线是 08:00。阅后消息、刷屏、付款或礼物不增加分数；没有连续签到奖励、断签扣分或公开排行。

任一方关闭后停止累计，并清掉当天尚未完成的双向活动；重新打开不补记关闭期间的行为。已累计分数不因短暂未聊天而扣除。删除、拉黑结束这一次关系，重新加好友不继承旧分数。

“密友 / 搭档 / 恋人”是双方确认的关系标签，与分数分开。提出邀请后须由对方接受才能生效；任一方可以解除。标签不授予数据访问、付款、账号或插件权限。

## 举报、证据与未知结果恢复

举报原因最多 500 个 Unicode 字符。举报某条消息时，必须属于举报人与被举报人的会话，且由被举报人发送；提交前再次确认目标、原因和是否附带正文。

正文证据默认不附带。用户明确开启“同意提交正文，独立保留 30 天”后，才复制当时仍可用的指定消息作为独立证据。阅后消息还必须已经由举报者开封且未过期；不能为了举报打开未读消息，也不能追回已过期正文。举报不会自动拉黑。

服务端将举报原因、目标等记录保留 30 天；证据存在独立的 `social_report_evidence`，从原举报创建时计算绝对 30 天期限。读取和重试都不延长期限。普通消息接口、通知和快照不读取证据；当前没有管理员审核界面或面向用户的证据下载接口。

`client_report_id` 在首次网络提交前保存。关闭页面、切号或重启后先用原编号查询仅本人可见的最小收据：`client_report_id / accepted / expires_at / server_time`，不返回原因、目标或正文。结果未知保留原意图；404 不等于自动创建新举报的许可。若需再次提交，沿用原编号、目标、消息、原因和同意状态。相同载荷重放不会多存一份证据，不同载荷返回冲突；过期或缺失原记录、应有证据时返回 410，不重建、不续期。

## 本地恢复与数据期限

已确认聊天历史和好友快照没有额外的客户端持久化缓存；页面内存与待确认写入分开处理。持久化记录都按发起账号隔离，登录其他账号不读取其内容。

| 数据 | 原生端 | Web 预览 |
| --- | --- | --- |
| Q 会话令牌 | SecureStore；退出先逻辑失效，再清理与撤销 | 仅内存 |
| 待确认普通消息 | SecureStore 分块保存原编号与原载荷，便于相同请求恢复 | localStorage 仅保存发起人、会话、消息编号与时长，不保存正文或令牌 |
| 待确认阅后消息 | 只持久化恢复编号等元信息，不保存阅后正文 | 同样只保存元信息 |
| 已开封阅后正文 | 仅当前页面临时内存 | 仅当前页面临时内存 |
| 待确认举报 | SecureStore 保存原编号、目标、同意状态、原原因及其摘要；不保存消息正文证据 | localStorage 保存原编号等元信息与原因摘要，不保存原因全文、证据正文或令牌；重试时需重新输入匹配的原原因 |

本地待确认意图在结果确认后删除；未知结果保留供原账号恢复，不因关闭页面或 401/429 新建意图。当前没有对这些本地待确认元信息设置自动到期时间。Web 重载后普通消息正文也不在本地；无法重构原载荷时先查原编号，不用空正文或新编号重试。放弃未确认消息前仍查询原结果，并由用户明确操作。

服务端期限区分如下：未处理好友申请 30 天；通知 30 天且每人最多保留最新 200 条；举报记录与证据绝对 30 天；未开封阅后正文 7 天，开封后按单条时长。普通消息、关系历史、消息封套和最小举报幂等收据当前没有自动过期策略。举报收据只保留发起人、原编号和原截止时间等防重建信息，不能恢复举报内容。

备份使用 [统一排除策略](../../backend/deploy/backup-policy.sh)，同时排除以下三张表的 **数据**，保留表结构：

- `social_ephemeral_payloads`：阅后正文。
- `social_report_evidence`：明确提交的正文证据。
- `social_reports`：举报原因及目标元信息，避免绕过 30 天期限。

封套和 `social_report_receipts` 的原始截止时间保留。恢复缺失正文、举报或应有证据时按不可用处理；原编号重放也不会重建，即使原截止时间尚未到。当前备份脚本对其生成的同机备份保留 14 天；其他普通数据、申请和通知在备份中的副本按备份策略保留，不能把在线清理理解为所有备份同时擦除。没有把同机备份称为异地备份。

## 运行与验证

默认前端启动仍只启动 Expo，不自动启动数据库或 API。真实社交联调另外启动已有后端：

```sh
npm --prefix mobile ci
npm --prefix mobile run dev
# 原生入口：npm --prefix mobile run dev:native

# 仅在明确需要本地后端联调时：
npm --prefix backend ci
npm --prefix backend run db:start
npm --prefix backend run dev
```

沿用 `DATABASE_URL`、`Q_BIND`、`Q_CORS_ORIGINS` 与 `EXPO_PUBLIC_API_URL`。客户端默认连接长期 HTTPS 服务 `https://q.kaicloudpay.com`；本机 Rust API 仍默认监听 `127.0.0.1:8787`。本地联调必须显式设置 `Q_LOCAL_API_TEST=1` 和本机 `EXPO_PUBLIC_API_URL`；Android 模拟器通过 `10.0.2.2:8787` 访问宿主。独立测试应用不要覆盖正式安装；真机不能把个人凭据发到任意明文局域网地址。真实社交不需要模型或视频供应商密钥；生产或内部部署配置继续关闭公开演示账号初始化 `Q_SEED_DEMO`，具体环境由 [后端说明](../../backend/README.md) 管理。

契约变化须运行 `npm --prefix mobile run api:generate`，不得手改生成类型。社交专项及提交范围内的基础检查：

```sh
npm --prefix mobile run typecheck
npm --prefix mobile run lint
npm --prefix mobile run test:social
npm --prefix mobile run test:account
npm --prefix mobile run test:chat
npm --prefix mobile run test:api-workbench
npm --prefix mobile run export:web

cargo fmt --manifest-path backend/Cargo.toml --check
cargo clippy --manifest-path backend/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path backend/Cargo.toml

# 先为下列测试配置独立、可丢弃的 TEST_DATABASE_URL；不得指向业务库。
cargo test --manifest-path backend/Cargo.toml --test social -- --ignored
cargo test --manifest-path backend/Cargo.toml --test postgres -- --ignored
cargo test --manifest-path backend/Cargo.toml --test social_backup -- --ignored

git diff --check
```

`cargo` 不在 PATH 时使用 `$HOME/.cargo/bin/cargo`。`social_backup` 会创建、恢复并删除独立测试数据库，需要相应测试角色权限、`pg_dump/pg_restore`（PATH 或 `Q_PG_BIN_DIR`）及 libpq 认证环境；它直接复用部署备份排除策略，不通过“文件里写了排除参数”代替恢复验证。完整移动端提交还需根规范规定的 utils、video、plugins 等检查；原生安全区、键盘、返回、前后台和媒体生命周期需设备验证。

社交真实 PostgreSQL 验收 14 项通过；实际 `pg_dump/pg_restore` 验收通过，三张排除表恢复后无内容且收据截止时间不变；移动端 social 19 项与 account 16 项通过。全量检查还覆盖现有 AI、API 工作台、插件、视频和账本，最新 MR 以其提交对应的流水线为准。

已完成 Safari 双账号联调：申请/接受、普通双向消息、已读、阅后开封和真实到期、亲密度关闭、标签确认、账号切换及举报存证确认。iPhone Air / iOS 27 / Expo Go 58 已检查登录、接受好友、原生文字接收/发送、阅后开封、到期及切后台后恢复；服务器再次读取过期消息返回 410。输入使用模拟器硬件键盘与辅助输入；软件键盘的完整尺寸矩阵、Android、iPad 和真机未全面验收。未使用真实供应商额度，未部署到服务器。

未开封证据的举报请求会先留下无内容拒绝墓碑，再返回 `SOCIAL_FORBIDDEN`；同编号后续查询或重放均为 410，不能因稍后开封而执行旧请求。客户端仅对该明确拒绝或明确到期终态按原编号清理待确认指针，网络错误、401、429 与载荷冲突仍保留原编号。

## 技术边界

当前采用前台约 3 秒一次的有界轮询，活动会话补拉消息、回执和阅后封套；写操作不自动重试。应用内通知不是 OS 推送，没有离线系统通知、WebSocket 或后台常驻连接。网络层有取消、超时和响应大小限制，关闭页面与账号切换会使旧响应失效。

服务端是现有 Rust 模块化单体中的 `social`，不新增聊天微服务、消息队列、缓存服务或第二套身份。AI 会话、MCP 连接与授权、视频凭据、模拟账本都不归社交模块；社交不自动把私聊送给 AI，不向插件开放私聊，也不按亲密度写余额。账号注册仍使用原来的身份/资料/模拟钱包事务。新增客户端依赖仅用于本地邀请二维码，不承担网络、存储或加密协议。
