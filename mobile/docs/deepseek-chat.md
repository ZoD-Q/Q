## 功能

- 默认 DeepSeek Flash（`deepseek-flash`），可选 Pro（`deepseek-v4-pro`）；深度思考显式开关。旧 `deepseek-chat/reasoner` 标识不再使用。
- 流式显示回答，支持停止、错误提示与手动重试。只有完整回答进入后续上下文，重试不重复用户消息。
- 历史按 Q 账号存入服务端 PostgreSQL；每页读取 20 个摘要，可继续加载，打开对话再读取消息。模型上下文仍按完整轮次选取，不缩短最新输入。
- 不把原始推理文本混入答案。附件、联网搜索和其他模型尚未接入，页面如实标注。插件工具已通过独立的提案、确认与结果续答链路接入，见 [MCP 宿主](mcp-host.md)；插件模式固定关闭深度思考。
- Chat 与 API 工作台共用 Q 身份。会话变更立即清理旧历史和侧栏标题，原生令牌仍在 SecureStore，浏览器令牌仅在内存。

## 银行插件模型流程（2026-10-22 源码）

选择银行插件后，所有新消息仍交给 DeepSeek，包括不同说法的余额问题、转账请求和普通聊天。客户端保留原文和完整轮次上下文，携带所选 `plugin_connection_id`，不再用本地关键词决定是否跳过模型。模型根据已提供工具选择回答、追问或生成提案；未选择插件时不会因文字出现银行名称而自动选择银行。“填写转账”位于输入框“+”菜单，只填入草稿，发送仍经过同一模型流程。

服务端从归属于当前用户的受信银行连接生成当前银行上下文：本人付款账户、银行名称与 ID 对照、本人自转和虚构陈小明的区别、港分金额单位及模拟资金边界。模型应追问缺失或含糊的收款人、银行和金额，不能把“朋友”默认成陈小明或把另一付款人替换为当前用户。第三方插件文字不能提供或覆盖这种宿主身份。银行插件继续使用普通模型模式，关闭深度思考；这不等于停用大模型。

模型选择工具后，服务器先校验并保存调用。2026-10-26 源码新增能力探测及可选 `automatic_readonly_tools`：仅受信内置银行余额/流水可直接完成，返回 `tool_proposal.automatic:true`；转账和未获可信只读策略的远程操作仍由用户确认。客户端读取原结果，确认聊天已保存且当前账号/页面仍有效后自动续答。已完成自然回答隐藏重复工具文字，原生图片和必要转账回执保留；模型失败仍展示真实结果。只有恢复失败时才显示“继续回答”，该操作只读取原调用，不重新确认执行。旧后端不收到新字段，继续以精简确认兼容。续答不会重复确认原转账，模型不能把业务失败描述为成功。详细设计见 [插件对话](plugin-chat-2026-10-26.md)。

旧版 `bankCommand` 历史消息仅保留显式重试恢复：以旧指令和原助手编号恢复可能已经准备好的提案，不新建替代幂等键或自动执行。所有新发送的消息都走模型。聊天历史中的插件只保存 `id / title / endpoint_url / connection_kind / builtin_service_id`；连接状态等运行资料不进入快照，结果未知的旧保存请求保持原编号与原载荷。

以上是源码流程，自动化替身能验证请求编排、确认边界与结果续答；真实 DeepSeek 对银行自然语言的理解、设备交互及发布状态须分别记录，不由本文宣称通过。银行边界见[银行合同](../../backend/contracts/banking.md)。

## 本地运行

密钥只放 `backend/.env` 的 `DEEPSEEK_API_KEY`，不要写入前端、`EXPO_PUBLIC_*`、日志或 Git。该文件需设置仅当前用户读写的权限。供应商地址固定为官方 HTTPS 接口，禁重定向和自动重试；没有配置密钥时会明确显示不可用。

普通使用只启动前端，默认连接长期运行的 `https://q.kaicloudpay.com`。只有明确进行本地接口开发时才分别启动本机后端与前端，且选择独立本地测试模式：

```sh
npm --prefix backend run db:start
npm --prefix backend run dev
Q_LOCAL_API_TEST=1 EXPO_PUBLIC_API_URL=http://127.0.0.1:8787 npm --prefix mobile run dev
```

如果开发数据库已经由另一个 Q 工作区启动，复用其 `DATABASE_URL`，不要同时在同一个端口启动第二份数据目录，也不要删除现有数据。本机 Rust API 是 `127.0.0.1:8787`；前端默认连接公网服务，显式本地测试可用 `EXPO_PUBLIC_API_URL` 配置（仅公开服务地址，不包含模型密钥）。默认 CORS 包含前端 8081；更换预览端口时同步 `Q_CORS_ORIGINS`。

AI 历史新增独立数据库迁移，须升级后端才能恢复和保存。注册沿用原有身份与模拟钱包流程；聊天不会将 QDC 演示余额作为真实费用扣除。供应商请求使用服务端配置的 DeepSeek 账户。

## 实现和验证

- Rust `backend/src/ai.rs` 负责鉴权后的流式代理、固定模型/地址、请求预算、限流并发、安全错误和取消。历史快照由独立鉴权接口写入数据库，日志不记录正文或密钥。
- `ai-chat/stream.ts` 解码真正的 SSE 帧，处理 UTF-8 分片、CRLF、注释保活、大小限制、超时和 Abort；意外断流不能算完成。

- `services/session-core.ts` 串行化所有会话存储操作，支持条件删除、过期写入回滚、原子版本快照和变更通知。

## 服务状态与恢复（2026-10-21）

公开 `/v1/ai/status` 只报告当前应用所连接的后端是否配置 AI，不验证 DeepSeek 额度或实时可用性。客户端分别显示检查中、尚未配置和检查失败；银行插件对话也保留配置状态和“重新检查”入口。选择或移除插件会刷新状态，但不会自动发送消息。状态 GET 独立于登录和对话生命周期，关闭登录弹窗、刷新状态不会取消彼此或正在生成的回答。短暂网络失败/超时/5xx 最多尝试三次，间隔 1 秒、3 秒，每次超时 8 秒；格式错误、鉴权错误和错误地址不自动重试。离页取消，重新进入前台或手动重查时重新检查。

失败保留最后一次已知配置，并如实提示它不是当前成功检查；不会因一次状态探测失败清除身份或草稿。没有缓存时必须先取得有效配置才发送。实际聊天 POST 仍不自动重发，用户通过手动重试处理失败，避免重复计费。网络、供应商停机或额度问题仍可能发生，这些恢复措施不是无限可用性承诺。

## 账号历史持久化（2026-10-21 源码）

已支持云端历史的后端：调用模型前先保存用户问题和待回答占位；保存失败不会调用供应商，保留输入草稿。结束、失败、停止及正常离页会提交最终快照。重新读取时把待回答和流式状态显示为已中断，不重放工具。操作系统强杀仍可能丢失未保存的流式片段，但已确认写入的问题可恢复。

客户端按账号令牌、对话串行保存，带请求 UUID 和期望版本。结果未知时保留原请求、原载荷，阻止新写入，显示未同步并支持手动重试；冲突不会覆盖远端，可点击“重载云端版本（替换本机未保存内容）”重新加载。仅当所有既往尝试都明确返回 `400 VALIDATION_ERROR`，用户显式重试同步且本机快照确有修正时，才以新请求 UUID 保存修正后的快照，继续使用原期望版本；未修改的快照沿用原请求。发生过网络、超时、5xx、401、429 或冲突等失败后，即使后来返回校验错误，也不会改变原请求。退出会等待已发出的保存再撤销令牌；断网和外部令牌撤销仍可能阻止最后快照。未确认请求仅在当前进程内存，重启后以服务器内容为准；更新应用、退出或重载前应先复制未同步内容。

每账号最多 100 个对话，每对话最多 2000 条消息，快照最多 4 MiB；超限显示保存错误并阻止新供应商请求。暂无删除与批量导出对话界面。

针对性检查：类型检查、Lint、聊天与会话 56 项测试通过，覆盖相同载荷重试、版本串行、响应校验、中断恢复与工具编号保留。设备交互和远端持久化验收另行记录，源码修改不代表已部署。

兼容旧后端：首次鉴权历史列表 GET 明确返回 404/405，且尚未成功读写云端历史时，进入明确标注的“仅本次会话”模式，核心对话继续可用。详情 404、保存失败、网络/超时/5xx 或会话失效都不视为未实现历史接口；已确认支持云历史后不自动降级。该探测按会话隔离，旧账号的晚到结果不改变当前账号模式；进入会话模式后保持到下次登录，不因后台升级而静默上传此前的本机对话。2026-10-21 探测时，线上 `4af1ed7` 尚无历史接口，列表返回 404；这是历史记录，当前部署版本另见[部署状态](../../backend/deploy/STATUS.md)。
