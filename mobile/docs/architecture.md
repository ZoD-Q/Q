# 小Q：工作区与领域边界

协作入口为 [根 AGENTS.md](../../AGENTS.md)，插件宿主目标见 [Q 插件接入规范](../../backend/docs/plugin-integration.md)。事实核对更新于2026-11-04；以下区分已实施模块、实际部署与后续规划，部署证据见[服务器状态](../../backend/deploy/STATUS.md)。

## 保留的首版后端与客户端能力

当前前端设计迭代独立于后端：`cd mobile && npm run dev` 仅启动 Expo UI。既有 Rust 业务、SQL/schema、账号和账本数据不因界面设计或目录整理而改动。

## 当前实施与部署

一个 Expo iOS/Android 客户端，一个 Rust API，一个 PostgreSQL 数据库。可注册和登录，编辑资料，选择浅色/深色/暖色主题与中文/英文，在两个账号之间转账模拟 QDC 单位，并查看各自流水。QDC与银行插件HKD始终是独立的演示账本；支付模块另有初始余额为零的HKD账本，不能混记或把演示资金兑换为真实资产。

普通用户独立Web产品仍未交付；`web/`已有`/q-admin/`静态管理演示页，Expo web仍作为移动端开发预览。DeepSeek、按账号持久化的AI历史、MCP连接和文字社交接口已部署。2026-11-03的API发布还包含应用主助手、公司研究协商、六家金融供应商目录及支付模块；2026-11-04复核主助手/公司研究版本均为1、受信只读能力开启，金融目录返回六项。真实供应商授权、全部应用工具的真实模型续答与支付实账闭环仍须分别验收。

保险、分期、理财和社区仍按实际开发状态展示。视频本地演示独立保留；API工作台复用identity，将个人可灵凭据和持久化任务交给后端video模块，不使用Q账本收费。支付报价和两渠道未支付收银台已验证；实际付款、审批、HKD入账及清算未实账验收，见[支付部署记录](../../backend/deploy/PAYMENTS-2026-11-03.md)。TestFlight构建5仅确认上传接收，公测处理/审核及公开下载状态仍待账号核实，不能由源码或服务器状态推断安装包已开放。

## 已实施领域

- identity：用户名、密码验证、会话签发与撤销。密码 Argon2；随机令牌只保存摘要。
- profiles：昵称、内置头像、简介、主题和语言。不得编辑身份、余额或权限字段。
- ledger：钱包账户、不可变记账分录、转账与幂等。唯一拥有余额写入权的领域；`ledger::bank_demo`单独保存银行模拟HKD，`ledger::real_hkd`独占支付HKD分录与余额写入，既有QDC不受影响。
- banking：20 家受信内置银行模拟插件和钱包投影，复用身份与插件提案/确认。银行卡产品参考图、余额、回执和流水进入现有钱包；不连接真实银行或模拟远程 MCP 授权。见 [银行插件](bank-plugins.md)。
- ai：鉴权后的 DeepSeek 文本流式代理、调用预算、取消和插件工具提案续答；通过 ai_history 按账号保存与恢复对话快照，不直接写余额。
- plugins：MCP 服务发现、个人连接、OAuth/CIMD 与显式确认后的工具调用；工具提案和结果按用户隔离，原生图片结果按需读取。Apps HTML 沙箱和公共索引仍未实现。
- video：个人供应商连接、加密凭据、生成请求去重与持久化任务；只接已明确适配的可灵接口，不承担公共发布或账本余额写入。
- social：双向好友、文字会话、阅后开封与到期、双向互动日、关系标签和举报；复用 identity/profiles，不读取 AI 历史或写账本。见 [社交说明](social-chat.md)。
- payments：CNY报价与收款编排、原请求幂等恢复、通知验签后服务端查单、双人入账审批和持久工作项；通过`ledger::real_hkd`在同一事务内记入独立HKD账本，不直接改余额。客户和操作员复用Q身份；未配置时关闭新报价。见[支付合同](../../backend/contracts/payments.md)。

欢迎演示金仍由注册用例调用ledger的模拟QDC发行流程记账，不进入支付HKD账户。支付没有KPS、真实账户间转账、银行出款、退款或真实资金审批管理页；返回应用或渠道通知均不能代替付款核实与入账审核。管理演示页不拥有上述业务权限。

注册是一个跨模块用例：identity 创建身份，profiles 建资料，ledger 创建钱包并发放模拟欢迎金；这些写入在同一数据库事务内完成。不能出现已创建身份却没有钱包的半成品账号。

## 账本不变量

1. 100个最小单位 = 1.00 Q、HK$1.00或人民币¥1.00。QDC、银行演示HKD、支付HKD各自独立分表；前两者只用于演示，CNY仅用于付款报价及证据金额，不代表存在CNY钱包。金额传输和记账使用整数最小单位；转账和充值本金拒绝小数、负数、零、越界金额，费用按支付合同允许为零。
2. 每个用户账户不可透支。模拟发行系统账户可以为负，用于对记欢迎金。
3. 转账双方账户按稳定 ID 顺序加锁；扣款、入款、两条分录和幂等记录在一个事务中提交。
4. 同一发起人、同一幂等键、相同请求只记一次；不同请求复用键返回冲突。
5. 旧分录不可修改或删除。后续纠错用新冲正交易。
6. 客户端余额仅用于展示。授权、金额校验、余额检查和记账始终由服务端执行。
7. 演示余额不能兑换或迁移为真实资产。支付HKD已经使用独立服务端账本及付款证据/审批关联；银行出款、退款和争议处置仍未实现，真实付款与清算须单独完成实账验收。

## Agent 协作

总协调负责接口合同、共享类型、mobile/backend 各自依赖锁、数据库迁移顺序及集成。实现 agent 按分配分别拥有 backend/、mobile/native/ 或工具文档目录，不得跨界改共享文件。每项交付必须附验证结果；账户隔离与账本不变量由独立黑盒检查复核。

## 视觉决策

三套语义主题：light（白底深墨、少量青蓝强调）、dark（近黑底）、warm（暖纸色与陶土点缀）。同一组 token 控制背景、文字、边框、强调色和状态色。当前原型默认 light，以聊天和输入框为首页中心，服务进入侧栏。历史 API 默认 warm；接回后端时需明确映射并保留用户偏好，不能把两个默认值混为一谈。

侧栏结构参考 https://ui.aceternity.com/components/sidebar 的宽屏侧栏/窄屏收起思路，以 React Native 组件重新实现；未复制其 DOM/CSS 源码，也未引入 Motion/Tailwind 依赖。React Bits 的 Blur Text 已评估但不采用：首版账户与钱包界面不需要文字模糊动效。
