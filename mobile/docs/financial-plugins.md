# 金融插件

2026-11-02。用户要求实施《小Q开放插件生态白皮书》第04节，在银行插件旁增加金融分类，并让用户通过个人连接调用同花顺 iFinD、金十、Massive、Alpha Vantage、Twelve Data、CoinGecko。此改动提供源码与接入路径，不自动部署、发包、购买数据或共享平台密钥。

## 使用路径

插件 → 金融插件 → 选择服务 → 添加个人连接 → 按服务要求配置个人密钥或在供应商页面授权 → 检查状态 → 在聊天中使用。服务连接、工具列表和实际调用结果各自核验，目录出现不代表授权完成。金融插件与现有银行模拟插件相邻，原目录参考和“我的连接”保留。

每个账号独立保存连接。密钥只在专用隐藏输入框临时输入，经已登录的小Q接口提交给服务端加密存储，不进入普通聊天、模型上下文或客户端持久化。关闭、提交或进入后台会清理输入。登录失效和供应商授权失败分别处理；供应商401/403不会将用户退出小Q。

使用OAuth的服务在官方授权页面确认其权限，返回后手动检查结果。添加或保存请求超时、取消时，先刷新已存连接状态，不能把未确认结果当作失败而盲目重复提交。断开清除该小Q连接的授权，不关闭供应商账号。

工具定义必须来自真实tools/list并通过有界校验，表内名称和范围不是本地虚构工具。每家采用明确选择的工具集合，控制单次模型上下文；不静默截取前32项，不声称覆盖供应商所有接口。供应商增加、删除或更改工具时，复用已有连接变更确认流程。

数据权限、费用、延迟和配额由供应商决定。个人账号权益不默认为所有小Q用户共享或允许商业再分发。本轮未购买或配置任何平台统一商业订阅。

## 受控协议兼容

通用远程插件保留现有2026-07-28、Card/Catalog与CIMD基线。金融分类采用服务端固定供应商登记，单独兼容官方端点的initialize、notifications/initialized及会话型Streamable HTTP；不把任意第三方Card升级到此路径。

连接继续使用remote_mcp，新增可选financial_provider_id，仅由服务端受控创建路径设置。旧客户端忽略附加字段后仍能读取已有连接，银行执行器不受影响。供应商、端点、认证方式和工具集合由服务端核对；客户端不能提交任意目标URL、请求头、执行器或协议配置。

Massive与Alpha Vantage的动态客户端注册只在固定官方授权来源内启用公开客户端和S256 PKCE；Twelve Data使用实际宣告的CIMD支持。该例外不是通用插件自动降级策略。供应商配置资料与真实MCP端点分开，不把本地登记包装成供应商发布的Server Card。

继续复用DNS/IP绑定、阻止私网目标、请求体与结果上限及禁止凭据请求重定向的网络层。初始化到一次业务调用整体受限，不通过无限重试延长调用；迟到、未知结果按原调用记录恢复。金十匿名挑战曾返回localhost授权元数据，不能跟随该不安全地址，固定密钥认证路径不读取它。

## 执行与历史

金融插件使用现有“模型提案 → 保存调用 → 用户确认 → 实际请求 → 保存结果 → 小Q解释”的路径。不会因为第三方声明readOnlyHint就继承内置银行的自动只读策略。通用数据调用或供应商远程代码工具仍需确认，代码不在小Q服务器执行。未取得结果不得声称查询成功；模型只能使用当前用户、当前连接版本的已完成调用记录续答。

更换个人密钥或重新授权会提升连接版本并取消旧待确认提案，旧结果不能回灌为新授权上下文。断开和删号清理相应密钥。主助手知道金融插件入口和连接限制，使用具体供应商时仍进入该个人插件对话，不隐式读取其他插件的私人结果。

迁移仅追加金融供应商标识、唯一约束与加密凭据表，不修改历史迁移、不清理账号或账本。旧客户端继续识别remote_mcp；旧后端回退后不提供金融专用连接能力，不应继续开放此入口。上线须同步更新后端与客户端，并在指定环境完成五家受保护服务的账号授权和业务验证。本轮没有部署、自动合并或发包。
