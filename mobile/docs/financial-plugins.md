## 使用路径

插件 → 金融插件 → 选择服务 → 添加个人连接 → 按服务要求配置个人密钥或在供应商页面授权 → 检查状态 → 在聊天中使用。服务连接、工具列表和实际调用结果各自核验，目录出现不代表授权完成。金融插件与现有银行模拟插件相邻，原目录参考和“我的连接”保留。

每个账号独立保存连接。密钥只在专用隐藏输入框临时输入，经已登录的小Q接口提交给服务端加密存储，不进入普通聊天、模型上下文或客户端持久化。关闭、提交或进入后台会清理输入。登录失效和供应商授权失败分别处理；供应商401/403不会将用户退出小Q。

使用OAuth的服务在官方授权页面确认其权限，返回后手动检查结果。添加或保存请求超时、取消时，先刷新已存连接状态，不能把未确认结果当作失败而盲目重复提交。断开清除该小Q连接的授权，不关闭供应商账号。

## 受控协议兼容

通用远程插件保留现有2026-07-28、Card/Catalog与CIMD基线。金融分类采用服务端固定供应商登记，单独兼容官方端点的initialize、notifications/initialized及会话型Streamable HTTP；不把任意第三方Card升级到此路径。

连接继续使用remote_mcp，新增可选financial_provider_id，仅由服务端受控创建路径设置。旧客户端忽略附加字段后仍能读取已有连接，银行执行器不受影响。供应商、端点、认证方式和工具集合由服务端核对；客户端不能提交任意目标URL、请求头、执行器或协议配置。

Massive与Alpha Vantage的动态客户端注册只在固定官方授权来源内启用公开客户端和S256 PKCE；Twelve Data使用实际宣告的CIMD支持。该例外不是通用插件自动降级策略。供应商配置资料与真实MCP端点分开，不把本地登记包装成供应商发布的Server Card。

继续复用DNS/IP绑定、阻止私网目标、请求体与结果上限及禁止凭据请求重定向的网络层。初始化到一次业务调用整体受限，不通过无限重试延长调用；迟到、未知结果按原调用记录恢复。金十匿名挑战曾返回localhost授权元数据，不能跟随该不安全地址，固定密钥认证路径不读取它。

## 执行与历史

金融插件使用现有“模型提案 → 保存调用 → 用户确认 → 实际请求 → 保存结果 → 小Q解释”的路径。不会因为第三方声明readOnlyHint就继承内置银行的自动只读策略。通用数据调用或供应商远程代码工具仍需确认，代码不在小Q服务器执行。未取得结果不得声称查询成功；模型只能使用当前用户、当前连接版本的已完成调用记录续答。

更换个人密钥或重新授权会提升连接版本并取消旧待确认提案，旧结果不能回灌为新授权上下文。断开和删号清理相应密钥。主助手知道金融插件入口和连接限制，使用具体供应商时仍进入该个人插件对话，不隐式读取其他插件的私人结果。

## 2026-11-08 搜索与临时宏观研究

新客户端请求 `catalog_version=2` 获取八家；默认/版本1仍返回六家，旧服务器返回六家时新增项显示尚不可用。内部供应商标识扩展经追加迁移完成；公开连接的 `financial_provider_id` 保留原六家枚举，Tavily/FRED 使用可选 `research_provider_id` 且原字段为 null。不能同时声明两类供应商，第三方 Card 不能选择任何固定适配。

Tavily 共享模式仅在固定官方端点发送 `X-Tavily-Access-Mode: keyless`，搜索与提取沿用具体确认及保存结果的流程。HTTP 200 中的共享额度错误也作为失败处理，不把付款/注册提示当研究成果。Alpha Vantage 的受控工具集合增加财报电话会、内幕交易与机构持仓，仍需实际 tools/list 与账号权益；工具变化先确认。401 提示重新授权，403 提示无访问权，402 提示套餐要求，429 提示稍后重试；非认证失败不会删除有效授权。

FRED 进入独立临时研究页。页面明确告知：查询和返回内容仅留当前内存，不保存到小Q缓存、调用结果存档、聊天历史或模型上下文；后台、离页、切号及卸载清除内容并取消请求。小Q只保存连接身份、加密授权材料和安全状态码，不保存 FRED 工具快照或请求/结果正文。响应包含 `Cache-Control: no-store` 与 `Pragma: no-cache`，普通工具/聊天/历史路径拒绝 FRED。没有“用于对话”或自动后台刷新入口。

FRED 页面提供[使用条款](https://fred.stlouisfed.org/legal/#MCPConnector)及非背书说明。授权采用固定 `https://mcp.stlouisfed.org/` 发行者和资源，保留尾斜杠、S256 PKCE 与 state；其专用 confidential DCR 客户端秘密只在现有加密封装内存储并绑定账号、连接、版本、发行者和资源，换码/刷新不接受上游替换秘密。此例外不改变 Massive/Alpha 的公开客户端或通用 CIMD 规则。

实施阶段公开探测：Tavily匿名初始化、工具发现和公开搜索取得结果；正文提取遇到共享额度错误，未记为成功。FRED仅取得公开授权元数据，尚无真实个人授权后的工具/业务验收。后续部署已验证FRED未授权响应的no-store，未调用其真实业务。SEC正文能力及边界见[公司研究](company-research.md)。目录上线不代表八家均完成授权或实账验证。

## 验收边界

匿名公开探测已确认CoinGecko的2025-11-25会话协商、工具列表、文档搜索及Bitcoin美元参考数据读取。五个受保护服务已核对官方文档、端点和公开认证元数据，尚无个人供应商密钥或真实账号授权后的完整业务验收证据，因此不能报告为已通过授权业务验收。服务器六项目录与配置标记返回成功，也不能替代供应商授权、真实工具调用或模型续答。下面保留上线前验证记录；部署与安装包状态另看[服务器状态](../../backend/deploy/STATUS.md)和[移动发布记录](mobile-release-2026-11-04/README.md)。TestFlight构建5仅确认上传接收，公测处理/审核及公开下载状态仍待账号核实，真机供应商操作未验收。

## 2026-11-15 个人额度与恢复体验（源码）

Tavily新增可选“共享额度 / 个人额度”。目录仍保留旧`auth_mode:none`，新服务同时宣告`access_modes`和`connection_access_mode`后，新客户端才提供选择；旧服务缺字段时保持既有功能。每个账号仍只有一个Tavily连接。省略模式的旧添加请求保留原模式（包括已断开连接）；切换模式必须先明确断开再添加，活动连接的冲突返回`PLUGIN_ACCESS_MODE_CONFLICT`。历史不删除，新版本隔离旧待确认提案、授权及工具快照。

个人模式在专用输入框接收Tavily API Key，经现有服务端加密保存，仅向固定官方端点发送Bearer，不带keyless请求头。未配密钥、401或额度失败均不退回匿名。连接标题与确认快照标示个人额度，保存密钥不等于查询已经成功。旧客户端的金融详情文案可能仍描述共享模式；个人额度配置和准确的模式管理须使用新版客户端，不把通用连接/历史兼容写成旧详情页完全支持。后端使用固定`financial-profile-2-personal`版本；第三方Card不能选择此身份。无迁移，但回退旧后端前必须禁用个人路径，不能将新模式解释为匿名共享。

金融错误提示区分目录接口缺失与个人连接删除；失效连接引导刷新或重新添加。服务能力待更新提供直达具体连接的核对入口；FRED仅管理连接更新并返回临时研究，不开放普通聊天、调用历史或通用工具。目录参考改以条目计数，原始ID、讨论组、内容和37条空占位保留；收藏仍明确是当前预览内状态。

CoinGecko个人MCP使用不同官方地址，当前公开授权元数据核验遇到TLS连接失败，不能据此猜测发行者或把API Key当OAuth token。本批保持匿名适配，个人入口待官方认证信息可核验后单独实现。同花顺个人试用不自动构成向小Q全部终端用户提供数据的许可；平台级共享需要确认官方授权范围、额度与计费，再另行实现后台集中凭据和用户级配额，不复制个人密钥给新旧用户。

自动检查、真实来源、原生界面与未完成项见[本批验证记录](plugin-improvements-2026-11-15.md)。本节不表示已部署、新手机包已发布或供应商实际授权验收通过。
