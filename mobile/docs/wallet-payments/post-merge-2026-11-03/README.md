## 确认并修复的问题

1. 历史订单 B 首次读取失败后，详情重试会查询主恢复中的 A；A 的后续读取也能令 B 详情变空。修复为按选中订单独立读取、取消与呈现，保留主订单原请求，不能据此创建重复充值。
2. 订单列表读取失败却同时显示“暂无充值订单”，把未知结果呈现成空记录。现在只有成功的空响应显示空列表；失败明确提示“暂时无法读取充值订单，请稍后刷新”。
3. 对修复中的重连、解除关联并发及页面切换另做确定性回归，防止内部 busy 不释放、旧读取令旧收银台再次可用，或误取消订单列表首次查询。它们是修复的防回归边界，不把自动化替身写成真实付款验收。
