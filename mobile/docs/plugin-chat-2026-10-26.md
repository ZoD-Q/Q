# 插件对话：直接得到结果

2026-10-26。根据用户提供的两张截图调整源码；不代表现有服务器或安装包已经更新。

## 交互目标

“轻”指用户只需表达需求，页面优先呈现可用结果。例如，输入“查询余额”，收到“你的中银香港模拟账户余额为 HK$100,000.00”（示例文案，实际金额取服务端结果）。不再把工具名、JSON、MCP 端点和调用阶段铺在对话里。

输入框仅保留当前插件的紧凑标签与移除按钮，删除“DeepSeek 理解你的请求并选择银行工具……”及通用插件流程说明。余额快捷按钮不再占一行；可选转账表单移入“+”菜单。继续复用语义主题、系统字体、16px 对话正文与现有留白：light 的白色底面、浅灰承托、青蓝强调与深色正文沿用 `DesignProvider`，dark/warm 不另造配色。移除图标有可访问名称；新增确认/查询按钮至少 48 高。

## 三种呈现

- 查询：短暂进度后直接给答案。服务端可证明只读的银行余额和流水在用户当前请求下自动完成，模型根据保存的真实结果回答。
- 操作：保留服务名称、完整的业务内容和一次明确确认。银行转账保留金额、收付款对象、模拟标记与滑动确认；不显示回执 UUID 或原始系统状态。
- 结果待确认：一行说明和“查看进度”，只读取原调用。取消、超时或重开页面不重新发起操作。

通用参数按不可变工具标题和 schema 标题形成可读字段/值；未知字段、嵌套、数组、空值、0、false 以及业务目标 URL 都保留，不把模糊标签当权限。控制及双向字符显式转义。正常结果隐藏传输 JSON；图片继续使用原生查看器，安全 HTTPS 资料以名称链接呈现。模型完整回答后不重复工具文字，但图片及经校验的简短转账回执仍保留。模型失败时保留真实结果供查看。

普通插件管理页只呈现服务、可理解来源、聊天入口及必要授权/更新事项；工具表、接口地址、原始数据和调用历史统一进入默认折叠的“高级设置”，按需加载。

## 执行与兼容边界

`GET /v1/ai/status` 的可选 `automatic_readonly_tools:true` 是新宿主能力。客户端只在观察到该能力时发送同名 opt-in 字段，旧服务缺少能力时保持精简人工确认，不发送未知字段造成 400。

当前自动允许列表仅为服务器所拥有的 `bank_demo` 余额与流水工具。模型、第三方名称、schema 文案和 `readOnlyHint` 都不能把转账或任意远程工具变成自动操作；所有远程插件共享精简外观，但未获可信只读策略的调用仍需一次业务确认。不是“所有第三方工具都可静默执行”。

自动查询先持久化调用，在同一事务内复核账号、连接、工具快照、版本及期限后读取结果。自动查询不伪造用户确认时间。客户端收到自动完成提示后仍读取原 ID、核对连接及完成状态；聊天写入成功后才继续回答。重载历史不自动请求模型，账号切换、离页和取消隔离延迟响应，一轮最多八份工具结果。续答失败仅在当时显示恢复入口；恢复不再确认业务操作。

主工作区的其他未提交改动保持原样。本轮使用基于已审核 `74d416f` 的独立工作区；API 合同与共享类型通过生成命令同步，无数据库迁移、运行库或 UI 框架新增。

## 验收

自动化覆盖协议能力兼容、只读策略、转账/恶意远程工具不自动执行、并发与账号隔离、取消/未知结果、历史写入失败、精简呈现与完整业务参数。真实第三方 OAuth、真实银行及供应商实账能力不由本轮 UI 测试证明。
