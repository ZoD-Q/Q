# 保险全景面板（2026-10-22）

入口：小Q侧栏 → 保险。当前服务路由使用 `prototype/insurance/page.tsx`；原有保险演示文件保留但不作为新目录入口。理财页面及原有三家公司内容未在本任务修改。

## 内容范围

以中国大陆常见商业保险为范围，提供 8 个导航板块、43 个保障入口。入口包含险种、附加险、产品形态和人群分类，**不是互斥的监管分类，也不是全市场在售产品数据库**。

| 板块 | 数量 | 内容 |
| --- | ---: | --- |
| 健康医疗 | 8 | 百万医疗、门急诊、中高端医疗、重疾、防癌、惠民保、商业长期护理、特药 |
| 意外出行 | 5 | 综合意外、境内旅游、境外旅游/留学、交通意外、少儿/老年意外 |
| 人寿养老 | 5 | 定期寿险、终身寿险、年金、养老年金、分红/万能/投连形态 |
| 车险 | 6 | 交强险、商业三者、车损、车上人员、新能源专属、附加险 |
| 家庭财产 | 3 | 家财、家庭/租客责任、宠物医疗/责任 |
| 企业责任 | 7 | 雇主、团体意外/健康、公众、产品、职业、企业财产/营业中断、网络安全 |
| 工程运输 | 4 | 建筑/安装工程、机器损坏、货运、船舶/航空 |
| 农业信用 | 5 | 种植、养殖、森林、信用、保证 |

目录支持中英文关键词与分类交集检索、空结果恢复、保障详情和最多三项对比（保留最近三项）。每个入口包含保障方向、重点核对、投保前询问清单、理赔材料参考。投保指南包含五步流程及常见疑问。沿用三主题和中英文界面；原生视觉验收为中文 warm 主题，其他主题和 iOS 尚未逐项设备验收。

## 分类双口径与监管归属（2026-11-03 增补）

目录在保留 8 大场景导航的同时，按《保险法》§95 与《健康保险管理办法》§2 为每个入口补充监管归属结构化字段，板块补充监管口径说明，形成「对外场景导航、对内监管归属」的双口径：

| 字段 | 层级 | 取值 | 说明 |
| --- | --- | --- | --- |
| `regClass` | 入口 | `life` / `property` | 监管大类：人身保险／财产保险（《保险法》§95） |
| `regSub` | 入口 | 枚举常量 | 监管细分：医疗保险、疾病保险、护理保险、意外伤害保险、人寿保险、年金保险、新型产品形态、财产损失保险、责任保险、农业保险、信用保险、保证保险 |
| `formTag` | 入口 | `main` / `rider` / `form-only` | 形态标注（互斥）：主险／附加险／形态类条目；形态类条目不计入险种数量 |
| `updatedAt` | 入口 | 日期 | 条目内容整理日期（初始基线 2026-10-22） |
| `sources` | 入口 | 官方来源数组 | 引用的公开目录（复用页面三家机构来源，按机构公开保障方向归属） |
| `regBasis` | 板块 | 文本 | 板块监管口径说明，供 agent 与维护者读取 |

板块映射要点：健康医疗全部落入健康险三类（失能收入损失、医疗意外暂无入口，为已知空白）；意外出行属人身保险交叉地带（财险公司经批准可经营短期意外险，一年期产品承保主体可为两类公司）；人寿养老末位条目为形态类；车险、家庭财产、工程运输、农业信用属财产保险；企业责任板块的团体意外/健康险是全目录唯一跨板块人身险条目。当前口径快照：43 个入口 = 主险 41 ＋ 附加险 1（车险附加险）＋ 形态类 1（分红/万能/投连）；人身保险 19 ＋ 财产保险 24。

检索：`findInsurance` 支持中英文关键词、板块、监管大类与形态的组合过滤，检索词库纳入监管大类与细分标签。Agent 的 `q_insurance_search` / `q_insurance_compare` 返回条目新增 `regulation` 字段（监管归属与形态），回答「重疾险属于哪类保险」类问题有据可依，无需改后端 schema。

目录测试同步扩展：监管归属非空、形态标注互斥、来源与日期必填、分类口径快照（43/41/1/1、19/24）、新维度组合过滤。

## 评级定位（2026-11-03 增补）

模块不评分、不排名、不比价，采用「信息完备度」导向的展示标准（《互联网保险业务监管办法》§23 禁止非保险机构比较产品、保费试算、设计投保方案；§15 禁止片面比价与简单排名）：

- 公司维度：不自行评级。咨询服务页提供官方评级引导：偿付能力充足率、风险综合评级与服务评价由保险公司和监管部门定期公开披露，引导用户查看承保公司官网或监管发布渠道的披露原文并注意数据期。
- 产品维度：以条款核对要点组织信息。详情页新增条目级监管归属、形态、整理日期与参考来源，并提示「备案信息请在承保公司官网核验」。
- 用户维度：保留投保前询问与如实告知指引；不建设风险测评工具（投保人风险承受能力评估是持牌机构义务）。

任何展示位置不出现「推荐」「优选」「Top」等排序语义词汇；新增文案不得削弱现有合规提示的显著程度。旧版演示页标题已加「示例」后缀，与知识目录区分。

## 后端预留

Rust `insurance` 模块新增公开状态接口及两个要求 Q 登录的预留接口。详见后端 `contracts/api.md` 与 `contracts/openapi.json`；共享类型已通过 `api:generate` 再生。

| 接口 | 当前行为 |
| --- | --- |
| `GET /v1/insurance/status` | 对话、咨询和个人数据接收能力均为 false |
| `POST /v1/insurance/conversations` | 验证身份与消息，返回 503 `INSURANCE_SUPPORT_UNAVAILABLE` |
| `POST /v1/insurance/inquiries` | 验证身份、主题与问题，返回 503 `INSURANCE_INQUIRY_UNAVAILABLE` |

主题为 coverage/eligibility/claims；消息和问题 trim 后 1–1000 Unicode 字符。拒绝未知字段、非法主题和 NUL。无数据库迁移，不保存咨询，不向外部发送信息，不创建会话或工单。前端显示服务未接通，不开放输入提交表单，不调用预留 POST。以后启用真实服务时还需对接供应商、按能力状态启用表单、实现归属隔离与数据处理规则。
